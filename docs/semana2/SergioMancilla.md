## Mis historias de usuario

> Producto: **Orilla** — pagos rápidos a economía informal / eventos.

1. Como **músico** quiero **una pantalla clara que diga “Te pagaron $X”** para **entender el estado sin jerga técnica**.
2. Como **trabajador** quiero **un botón grande “Enviar a Bancolombia”** para **completar el cash-out sin perderse en menús**.
3. Como **pagador** quiero **una vista de progreso del lote (enviados / pendientes / fallidos)** para **saber si ya puedo cerrar la operación**.
4. Como **usuario nuevo** quiero **un onboarding de 3 pasos máximo** para **empezar a cobrar el mismo día que me invitan**.
5. Como **trabajador** quiero **compartir o guardar el comprobante del pago** para **mostrárselo al hotel si hay disputa**.
6. Como **pagador** quiero **corregir un número de celular erróneo antes de lanzar** para **evitar pagos que nadie puede reclamar**.
7. Como **diseñador / producto** quiero **que el flujo mobile-first funcione en redes lentas** para **que sirva en el cierre del evento en sitio**.

## La más importante y por qué

| Orden de importancia | Historia # | Por qué |
| :---: | :---: | --- |
| 1 (la más importante) | #2 | Es el momento mágico del MVP y lo que diferencia a Orilla de “solo crypto”. |
| 2 | #1 | Sin claridad de “te pagaron”, no hay confianza ni fibra. |
| 3 | #4 | Reduce abandono en el primer uso (staff / músicos). |
| 4 | #3 | El pagador necesita feedback operativo del lote. |
| 5 | #5 | Soporte a disputas; refuerza comprobante. |
| 6 | #6 | Calidad de datos del lote; evita soporte. |
| 7 (la menos importante) | #7 | Requisito no funcional; guía implementación pero no es una feature sola. |
